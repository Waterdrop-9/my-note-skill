# Exemplar · 模仿讲解理由，不复制主题

需要校准教学风格时读取。项目根目录的 `笔记.md` 是一份写作规范，包含少量衔接写法，不是一篇完整的技术事实材料。以下是对其方法的提炼与新构造的泛化例子，日常使用 Skill 无需加载原文件。

## 为什么这些组织方式有效

| 从 `笔记.md` 提炼的思想 | 工程化落点 | 好在哪里 |
| --- | --- | --- |
| 先建立任务大图景，再由缺口引入机制 | knowledge-chain 的六字段蓝图 | 读者知道下一节为什么需要出现 |
| 评价结果还没有变成参数更新信号 | Previous / Gap / Bridge 与问题回收 | 已有产物与缺失步骤分开，过渡本身在解释 |
| 公式前提问题，公式后读符号与整体意思 | technical-depth 的公式与推导契约 | 数学是问题的精确回答，不是装饰 |
| 条件 → 操作 → 结果 → 人话 | pedagogy 的分支展开与类比约束 | 读者改变条件后还能预测，不只记住故事 |
| 难点深入，旁支止步 | 三层优先级与具体停止标准 | 不因困难牺牲主线，也不无限补前置 |
| 正文解释先成立，再压缩口述回答 | interview-priority 与 content P0 | 面试区可追溯，不产生第二套知识体系 |
| 排版服务理解，提示块各有功能 | 语义布局映射与双重 QA | 视觉结构与知识关系一致 |

## 衔接例子：数据库

“索引已经缩小了候选记录的范围，但查询还需要索引中没有的列。于是还要访问原记录。现在可以追问：如果索引本身包含查询需要的值，能否省掉这部分访问？代价是索引更大，写入时也要维护更多数据。”

好的地方：每个新问题由上一环节产出，没有把方法名当连接词。具体能否省访问还要依据数据库的存储和可见性规则，不能从教学直觉直接推成所有数据库的保证。

## 难点与类比例子：容量为 2 的缓存

访问 A、B、A 后，按最近使用排序是 B、A，而插入次序仍是 A、B。放入 C 时，LRU 淘汰 B；FIFO 淘汰 A。

先展示差异，再给操作：“命中 → 移到最近使用端 → 满时淘汰另一端”。最后才压缩为“用过就重新排队”。这里队伍映射访问次序；它不意味着按价值排序，更不能保证预测未来。

好的地方：小例子正好揭示两个概念的断点，随后可迁移到别的访问序列。更多缓存变体不会自动成为必读。

## 面试压缩例子

在正文已解释访问顺序与淘汰后，回答可以压缩为：“LRU 在容量有限时淘汰最久未使用的条目，用近期访问作为复用线索；因此命中也必须维护顺序。它需要元数据更新，并可能被循环扫描拖低命中率。”再追问“命中不调整顺序会怎样”，回到正文的 A、B、A、C 例子。

好的地方：结论、原因、边界都能回查正文；没有突然冒出一组未解释的缓存八股。

## 跨主题验收练习

用真实请求手动检查 Skill 的行为，不只匹配标题或关键词：

1. **已懂基础 Policy Gradient，想弄懂 importance sampling、GAE、PPO clip，目标算法面试。** 检查知识链是否从已有方法的具体缺口出发；优势估计与旧数据校正各自解决什么问题，是否明确为可配合的机制；clip 的分支是否可从公式推出，是否区分单样本项与总体更新。不得把教学顺序写成历史必然，也不能声称 clipping 保证所有 ratio 留在区间内。
2. **懂字典，第一次学缓存淘汰，20 分钟。** 检查是否解释容量约束、命中更新次序、代价与失效模式，是否将分布式一致性等不影响当前闭环的内容留作选读。[完整 HTML 示例](../examples/deep-study-cache.html) 展示这一范围。
3. **把这段旅行记录做成皮革手账。** 应选择 B，保留原内容范围，不强加数学、技术知识链和面试题。
4. **技术材料用 Style A，只做排版。** 应保留 A 的视觉与原文事实，不因为技术关键词改用 C 或扩写新结论。

这些是验收情境，不是所有笔记必须照搬的章节模板，也不是已经完成的独立模型评测。
