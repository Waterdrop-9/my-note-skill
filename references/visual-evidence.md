# Visual Evidence · 来源图表与多样化表达

当资料含关键图、表、曲线、截图，或视觉表达能显著减少解释成本时读取。图不是装饰：它必须承担结构、机制、数据证据或对比中的至少一种作用。

## 先做图表盘点

读资料时记录候选图的来源位置、它回答的问题、读者必须看到的元素，以及正文是否能更清楚地替代。优先保留以下视觉材料：

- 架构或数据流只有放在整体图中才能看清模块关系；
- 实验曲线、消融表或可视化本身就是结论证据；
- 原作者的符号、坐标或分区会在后文反复引用；
- 截图展示了真实界面、执行状态或故障现象，文字重述会丢信息。

普通定义、短因果链和能用两三句话讲清的关系不必强行配图。不要给每节设图片配额，也不要为了“更丰富”复制整篇资料的图。

## 复用顺序

1. **直接复用原始图片文件。** 来源提供清晰图片时，下载或复制到成品的 `media/`，保留原始比例，不用远程热链。
2. **截取关键图表。** PDF 或网页没有可单独取得的图片时，只截完整图表区域，包含坐标轴、图例、标签和必要的原图编号；不截浏览器栏、导航和无关正文。
3. **忠实改绘。** 原图分辨率不足、结构过密或复用不合适时，可用 HTML/CSS 或内联 SVG 重画关系；数据图不得凭目测重新造数值。图注明确写“据来源改绘”。
4. **回退为文字或表格。** 无法可靠取得或读清时，不留下破图占位；用正文解释并标出资料缺口。

同一张图只保留一个最清楚的版本。裁剪只移除无关边缘，不删除会改变结论的图例、轴、误差线、注释或对照组；不去除水印和署名。

## 图注与可访问性

每张来源图紧邻以下信息：

- 简短标题：这张图帮助回答什么；
- 一两句读图结论：先看哪里、能推出什么、不能推出什么；
- 来源链接与论文页码、图号或网页小节；
- 标注“原图”“局部截取”或“据来源改绘”。

`alt` 描述图的教学作用和主要关系，不重复文件名，也不把完整正文塞进去。复杂图可让图片链接到本地原尺寸文件，正文仍需讲出核心结论，不能要求读者只靠看图猜。

```html
<figure class="source-figure">
  <a class="figure-frame" href="media/source-figure.png" target="_blank" rel="noopener">
    <img src="media/source-figure.png" alt="策略、奖励与更新步骤之间的数据流" loading="lazy" decoding="async">
  </a>
  <figcaption>
    <strong>先看什么：</strong>奖励同时进入优势估计和策略更新。
    <span class="figure-credit">原图截取：<a href="https://example.com/source">来源标题，图 2</a></span>
  </figcaption>
</figure>
```

## 选择不同视觉形状

视觉结构跟着问题走，不把所有关系压成同一种卡片：

| 要回答的问题 | 优先形式 |
| --- | --- |
| 模块如何连接、信息往哪里流 | 来源架构图、流程图或简洁 SVG |
| 指标如何随时间／规模变化 | 原始曲线图；保留坐标、单位和误差信息 |
| 哪个阶段产生、冻结或消费变量 | timeline、swimlane 或 process |
| 条件变化后走哪条路 | 决策树或机制表 |
| 两种方法在哪些维度不同 | 对比表、二维矩阵；维度少时用 compare |
| 一个公式中的项分别控制什么 | 公式旁注或分解图，正文保持同一符号 |
| 代码运行时发生了什么 | 调用链、状态图或关键界面截图 |

图、公式、流程与正文必须描述同一件事。图中命名与正文不同就给映射，不能为了版式好看改变箭头方向、数值尺度或因果关系。

## 最终检查

- 图片已落到交付目录，移动整个笔记目录后仍能加载；
- 桌面和窄屏不变形、不裁掉标签，需要时局部滚动或打开原图；
- 图注、来源、图号／页码和复用方式可见；
- 正文明确解释关键观察，图没有替代技术论证；
- 没有把同一信息同时做成原图、表格和卡片造成重复。
