# Content Quality Checklist

草稿完成后、布局之前检查；排版中内容发生变化时重查受影响项。它和 [Visual Quality Checklist](checklist.md) 是两个独立门槛。

## 执行方法

逐项对照正文，内部记录“通过 + 章节证据”“失败 + 修订点”或“不适用 + 原因”。没有公式的主题可将公式项标不适用；核心公式未写不能用不适用掩盖。仅美化已有文本时检查事实保真、衔接与内容完整性，不扩张用户范围。

任何适用 P0 失败，返回正文修正后复查。P1 按目标改进；无需在成品展示审查表，也不以自动查到关键词代替教学质量判断。

## P0 · 内容正确性与理解门槛

- [ ] 开头建立 big picture：任务、朴素办法、主要缺口、各核心机制的位置。
- [ ] 读者基础、生成目标、时间预算、资料范围与内部优先级计划只用于写作决策；成品没有提示词式的任务复述或 meta 清单。
- [ ] 每个核心概念在定义或实现前解释 why：为什么存在、没有它会发生什么。
- [ ] 相邻重要章节有真实因果、前置依赖、数据流或明确的分支／对比关系。
- [ ] 前文留下的问题被后文接住，或明确说明范围外；不存在未兑现的预告。
- [ ] 章节由当前主题的依赖、推导、执行流、比较或证据组织；没有为了贴合模板而硬凑固定节数、固定编号或固定卡片组合。
- [ ] 过渡说明具体已解决问题与剩余缺口，不仅是“上一节 A，本节 B”。
- [ ] 核心公式解释了要回答的问题、整体含义、符号和必要条件。
- [ ] 推导没有初学者跨不过去的关键跳步，消项／替换／交换操作有理由。
- [ ] 区分 definition、theorem、精确关系、estimator、approximation 和实际替代目标。
- [ ] 区分训练／推理或对应的系统阶段，交代变量来源、更新／冻结及必要的梯度路径。
- [ ] 抽象效果落实到具体改变的量／操作及因果机制，适用边界和代价没有省略。
- [ ] analogy 的角色、动作和条件准确映射 mechanism；改变条件后仍能预测行为。
- [ ] analogy 未替代技术解释或论证，措辞力度没有超出公式及证据。
- [ ] CORE / FOLLOW-UP / OPTIONAL 与目标匹配，主线必需的难点没有降为选读。
- [ ] 核心内容达到可独立复述的程度；重要章节有具体掌握标准。
- [ ] 面试回答来自正文压缩，递进追问的回答要点能回到正文找到解释。
- [ ] 没有低 ROI 八股堆积，也没有为了显得高级无限追溯旁支。
- [ ] 没有为了版面、固定高度或篇幅删除关键推导、桥接、原因、断点、例子及边界。
- [ ] 理论、流程、表格、代码中的变量、条件、结果一致，教学例子可复算。
- [ ] 事实有适当依据，风格 exemplar 未冒充事实来源；缺口／冲突／教学假设明确。
- [ ] few-shot 只迁移教学方法和组件用法；没有引入当前主题不需要的示例术语、章节或公式，领域专属检查只在适用时执行。
- [ ] 复用的来源图表保留决定结论的标签、坐标、图例与上下文，正文解释关键观察，图注给出来源定位和复用方式。
- [ ] 具体性能、版本、配置和外部研究结论可核查；未执行的代码未声称通过测试。

## P1 · 复习与表达质量

- [ ] 分支先展开再归纳，最后的记忆句能准确唤回机制。
- [ ] 比较使用共同决策维度，读者能解释在给定条件下为什么选它。
- [ ] 代码注释解释 why，必要 shape／单位清楚，简化范围明确。
- [ ] 普通代数和无关扩展得到克制，正文以连贯段落推进。
- [ ] 章节组合随知识关系变化；同义提示可复用，未把一致视觉语言误判为内容重复。
- [ ] 全文末尾紧凑回顾主线，不再复制一份正文；选读说明什么时候值得继续。

## 一个实际审查动作

任选关键章节，暂时遮住标题、颜色和比喻：只读正文能否回答“为什么现在需要这个概念，具体改了什么，为什么有效，条件变了会怎样”？不能就补解释，再排版。

## 通过后的交接：语义识别

内容 P0 通过后，按 [语义布局](layouts-deep-study.md#先识别语义再选择强调强度) 识别洞察、危险误解、公式、条件分支、流程、转折、追问及回顾答案，给已有重点安排可见落点。此时只判断内容承担什么学习功能；实际是否醒目、是否装框过密、是否只定义 CSS 而未使用，交给 Visual QA。内部记录不进入正文；读者使用的学习标签与正常引用保留。
